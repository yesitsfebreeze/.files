# Machines.txt — provisioning, secrets, remote access

Last updated: 2026-09-29

## The order contract

install.sh on a fresh clone: Homebrew -> brew bundle (Brewfile) ->
Remote Login -> tmux-mcp -> tmux plugins -> deploy.sh LAST. The hooks
generate shell init by RUNNING the tools; a tool installed after the
deploy is a tool the generated init does not know about. Homebrew 6
refuses untrusted taps — `brew trust --tap tinted-theming/tinted` is in
install.sh because tinty owns the palette and `brew bundle` will not
trust a tap for you.

## Secrets are runtime, never deploy-time

Nothing in the tree holds or computes a secret. The TypeSafe key is read
from the Keychain at first interactive shell (bounded 3s, handed to the
tmux server env so every pane inherits it). Capsule credentials are
Keychain reads in a background job at container start. The deploy has no
templates at all — the gitconfig identity is plain text.

## Remote access

A tailnet peer reaches this machine over the BUILT-IN sshd (Remote Login)
with a key — the Tailscale GUI app cannot be an SSH server on macOS, and
public tunnels failed every chat's URL reader (serveo/pinggy "Continue"
pages, Cloudflare 403s). install.sh loads the sshd launchd job (one sudo
prompt; launchctl, not `systemsetup`, which wants Full Disk Access).

## Host scope

macOS only. Homebrew paths are /opt/homebrew. The nushell history lives
in sqlite at $nu.history-path (a launch-time constant — it follows
XDG_CONFIG_HOME from the LAUNCH env, which is why env.nu's own XDG
assignment cannot move it).

## Known traps that bit once

- A `cd` after a crashed full-screen TUI staircases the listing — stty
  sane runs in the PWD hook, gated by the TUI sniff (a per-cd spawn tax
  buys nothing in the normal case).
- At 0 terminal columns an EMPTY directory listing spins nushell at 100%
  CPU — the listing hook tests width first.
- `stty` lookups use `which`, never `e> /dev/null` — nushell raises
  external_command BEFORE any redirect can guard it.
