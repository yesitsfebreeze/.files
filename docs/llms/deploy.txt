# Deploy.txt — how this repo becomes the machine

Last updated: 2026-09-29

## The shape

home/ keeps REAL filenames — what you see in the tree is what lands in
$HOME. There is no manager (chezmoi is retired, commit 0fc7dee): dotfiles.sh
is the whole deploy, and it is a REPLACING mechanism, not a templating one.
Nothing is computed at deploy time; dynamic values are runtime concerns.

## dotfiles.sh (repo root)

    sh dotfiles.sh                # deploy (what `rr` and `just deploy` run)
    sh dotfiles.sh --status       # dry-run: NEW / DIFFERS / RETIRE
    sh dotfiles.sh --adopt <path> # copy a live file back into home/

Five steps, in order, each explicit in the script:

1. PATH first: brew shellenv + ~/.local/bin + ~/.cargo/bin — the hooks run
   tools, so a tool the PATH step installs must be findable when they run.
2. The preflight exec-bit guard: every .sh and every .local/bin file must
   be +x in the tree or the deploy warns — the rename once shipped three
   dead scripts, and this makes a repeat impossible to miss.
3. The copy: every file under home/ overwrites its target in $HOME
   (cp -p; modes ride along; git tracks the exec bit, no name prefixes).
   .DS_Store, .git and __pycache__ are excluded by the find.
4. Retirements: every path in removed.txt is deleted from $HOME. Retiring
   a file is TWO EDITS and always was: delete the source file, append the
   target path to removed.txt. The sweep is idempotent (rm -f).
5. Hooks: hooks/*.sh run in a fixed order, each with `|| warn` — one
   failure warns and the rest still run. The order in dotfiles.sh:
   generate-shell-init, install-claude-hooks, register-mcp,
   seed-mason-registry, sync-claude-plugins, reload-tmux (last, because a
   running tmux keeps the config it started with — see reload-tmux.sh).

## --status and --adopt

`--status` is the dry-run chezmoi had (`diff`) plus the drift report it
never had: NEW (no target yet), DIFFERS (source and target disagree —
WHICH SIDE moved is `git status` in the repo; there is no state database
by design), RETIRE (removed.txt paths still present). It changes nothing
and runs no hooks. `--adopt <path>` is the reverse direction — the
`chezmoi add` equivalent: a live file under $HOME is copied into home/ at
its own path, refusing anything outside $HOME or containing `..`.

## rr (the daily loop)

`rr` in nushell = git pull in $env.DOTFILES + sh dotfiles.sh. $env.DOTFILES
is set in env.nu (~/.config/nushell/env.nu) to ~/dev/dotfiles. Editing any
file in home/ is live the moment you deploy; there is nothing to "apply"
afterwards.

## install.sh (a fresh machine)

Order is the contract: Homebrew bootstrap + brew bundle (Brewfile) ->
Remote Login (sshd over the tailnet) -> tmux-mcp binary -> tmux plugins
(resurrect, continuum, cloned to ~/.local/share/tmux/plugins) -> dotfiles.sh
LAST, because the hooks generate shell init by running the tools the PATH
step just installed. A failed package warns; the run continues.

## hooks/ (repo root)

- generate-shell-init.sh — writes ~/.cache/nushell/init/{zoxide,television}.nu
  from `zoxide init nushell` / `tv init nu`, tmp+mv atomic, truncated (never
  missing) on failure — a missing file would be a parse error in every
  shell (config.nu sources all of them).
- register-mcp.sh — tmux-mcp registration for Claude Code, USER scope, into
  ~/.claude.json (NOT settings.json — that block is ignored there).
- install-claude-hooks.sh, sync-claude-plugins.sh, seed-mason-registry.sh —
  idempotent wiring for the Claude/Neovim side.
- reload-tmux.sh — unconditionally `tmux source-file` (idempotent) plus a
  warning to any client without terminal feature `sync`.

## Removed.txt

The retirement ledger. Currently-retired paths include .config/starship.toml
(the prompt is nushell now), .config/chezmoi, .chezmoiignore, .config_x.
Keep it append-only; entries run `rm -rf` on every deploy.
