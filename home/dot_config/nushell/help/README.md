# `help` content model

The manual is data, not prose kept beside the code. Four `.nuon` surfaces hold
every entry; `help` reads them straight, and `just manual` renders the same
entries to markdown that `?` greps.

## Files

| File | What it is |
|---|---|
| `topics.nuon` | the spine: the nine topics in reading order, with summaries |
| `tasks.nuon` | the guide's spine: the fourteen tasks, with intros |
| `shell.nuon` | nushell — keybindings, aliases, custom commands, idioms |
| `nvim.nuon` | Neovim — keymaps, plugin keys, and the core keys we keep |
| `terminal.nuon` | WezTerm and tmux — windows, panes, copy mode, clipboard, capsule bindings |
| `capsule.nuon` | the capsule CLI and what a container gets from the host |
| `manual/` | not content: the manual as markdown. `manual/guide/` and `manual/reference/` are GENERATED by `scripts/generate-manual.mjs` (`just manual`) and must not be hand-edited; `manual/internals/` and `manual/index.md` are hand-written |

NUON, not YAML: `open shell.nuon` in nushell returns a table with no parser and
no dependency. Comments are legal and used for section headers.

## Entry schema

Every entry is a record. Field order below is the order entries are written in,
so a diff reads top to bottom.

| Field | Required | Meaning |
|---|---|---|
| `key` *or* `cmd` | one of the two | the binding (`Ctrl-R`, `F5 <digit>`) or the invocation (`z <query>`) |
| `title` | yes | one line, imperative, no trailing period |
| `use` | yes | the real gesture in order: what to press next, and what comes back. A `key` entry never *opens* by restating its key, backticks included |
| `topic` | yes | one of the nine in `topics.nuon` — the REFERENCE's spine, grouping by subject |
| `task` | yes | one of the fourteen in `tasks.nuon` — the GUIDE's spine, grouping by what you are trying to do. Deliberately independent of `topic`: an agent's capsule credentials are a `containers` topic and an `agents` task |
| `step` | yes | integer, this entry's order on its task page |
| `does` | optional | a shared id for two entries that are two ROUTES to one capability — a key and a command, e.g. `Ctrl+Shift+D` and `capsule [dir]`. The guide renders them as one block, which is what stops the same thing being listed twice. Both still answer to `help` under their own names |
| `kind` | optional | `concept` for an entry that explains something rather than naming a command (`mkcd`, `the status bar`, `ssh in a capsule`). The guide renders these under their title instead of as code |
| `mode` | yes | `shell` · `nvim:normal` · `nvim:visual` · `nvim:insert` · `terminal` · `container` |
| `also` | optional | related entries, by `key`/`cmd` |
| `why` | optional | the non-obvious reason it works this way — a constraint that cost somebody a day, and nothing the `use` already said |

`verify` and `source` were removed on 2026-09-02 with the drift checker that
read them. `source` had gone stale in a way nothing could see: all 116 values
named `prds/<...>/prd.md`, and the board moved to `.pearde/prds/` — so the
generator was printing a `Spec:` line of dead paths onto every manual page.

**Present is not enough — every value has a shape.** A field spelled correctly
and holding nothing is the failure this schema shipped with for three cycles:
`key: ""` reads as a filled entry and documents nothing. Write the value or
leave the optional field out.

## Changing it

1. Edit the `.nuon` surface. It is a nushell table — `open shell.nuon` to read
   it, and a stray comma or brace shows up as a parse error on the next `help`.
2. Run `just manual`. This regenerates `manual/guide/` and `manual/reference/`
   from the surfaces; commit them with the source in the same change.
3. Run `chezmoi apply` and use the thing you documented.

Nothing checks the manual against the configuration. It was checked, by a
497-line drift check that spawned a headless Neovim, a second tmux server and a
WezTerm probe; it was deleted on 2026-09-02 along with the tests, because a
check that takes a minute to say what deploying the change says in a second is
a cost with no reader. **So the entry is part of the change, not a follow-up:
if you add a key and not its entry, nothing will tell you.**
