You rarely type a path here. Zoxide learns where you go and ranks by frecency, so a fragment is enough — and a bare word with no command is treated as a jump. Every route lands in the same funnel, so the start directory, the back-stack and the recents log stay correct however you moved.

## `<word>`

**Jump by typing a directory name on its own**

*shell*

Type a bare word that is not a command — `dotfiles` — and press enter. If zoxide knows a directory matching it you land there with a cleared screen; the fresh prompt in the new directory is the confirmation. If it knows nothing, you get the ordinary command-not-found.

<Callout title="Why it is this way">
The jump happens in `pre_execution` because that is the only hook where a cd persists, and the screen is cleared in `pre_prompt` to bury the command-not-found error that is already on its way. The trigger is deliberately narrow — first token unknown, no shell metacharacters, not path-shaped — so `./x` and `ls | nope` never jump. It queries `zoxide query --exclude $PWD` directly and only jumps on a real hit, because the funnel reads an empty argument as no argument at all and would otherwise take you HOME on every miss.
</Callout>

See also: [`z <query>`](/docs/guide/directories#z-query) · [`zz`](/docs/guide/directories#zz)

## `z <query>`

**Jump to a directory by a fragment of its path**

*shell*

Type `z` and any part of the path — `z dot` reaches ~/dev/dotfiles. Zoxide picks the best frecency match and you land there; the listing prints itself. A single argument that resolves to an existing *file* opens it in nvim instead of jumping, so `z notes.md` edits.

<Callout title="Why it is this way">
Every jump goes through the `cd` funnel, so the start dir, the dirstack and the recents log update no matter which route you took. A jump that does not move PWD logs nothing — a failed `z` leaves no trace.
</Callout>

See also: [`zi / cdi`](/docs/guide/directories#zi-cdi) · [`zz`](/docs/guide/directories#zz) · [`<word>`](/docs/guide/directories#word)

## `zi / cdi`

**Pick a directory from zoxide interactively**

*shell*

Run `zi` — or `cdi`, the same command under the name muscle memory reaches for — with no argument and the zoxide database opens in an fzf picker, ordered by frecency: type to narrow it, then `Enter` on a row and you land there. The picker is fzf, not television — it shells out to `zoxide query --interactive` — and it is the one accepted exception to tv owning every picker screen.

<Callout title="Why it is this way">
The exception was granted rather than tolerated: drawing this list from a cable file would mean reimplementing zoxide's frecency ranking inside television, and that ranking is the only reason the list is worth opening. So fzf sits in the required package set as zoxide's dependency, never as a picker anything else may reach for — a second picker outside tv is a new decision, not an appeal to this one. Decided 2026-08-21 (user).
</Callout>

## `zz`

*shell*

## `zl <query>`

**Jump to a directory and list it**

*shell*

Give it the same query `z` takes, directories only — there is no file-opening branch here, unlike `z`. It runs `la` in the directory it lands in, and because the PWD hook already lists after every interactive move, in a terminal that means you see the listing twice: `zl` adds a listing of its own rather than replacing the hook's.

## `cd <path>`

**Enter a directory, creating it if it does not exist**

*shell*

Point `cd` at a path that is not there and it offers to make it: press `Enter` to confirm and you are in the new directory. Any key that is not blank prints `aborted` and cancels, so the reflex `y` is a cancel — while `Space` and `Tab` confirm, because the check is for a non-blank keypress rather than for `Enter`. `cd` alone goes home, `cd -` toggles back. Everything else about it is the builtin.

<Callout title="Why it is this way">
`cd` is aliased to the `mkcd` wrapper, which is the single funnel every kind of navigation reaches the shell through.
</Callout>

See also: [`mkcd`](/docs/guide/directories#mkcd) · [`z <query>`](/docs/guide/directories#z-query)

## Understand the one funnel every move goes through

*shell*

Nothing to run — this is the shape of the shell. Real `cd`, zoxide jumps, picker jumps and the bare-word fallback all arrive at `mkcd`, and the PWD hook is the single place that reacts to a move.

<Callout title="Why it is this way">
Because there is exactly one funnel and exactly one reaction point, four things stay true however you moved: the directory is recorded to `startdir.txt` so a new pane opens where you left off, it is pushed onto the dirstack that feeds the recent-dirs picker, the pick is logged to the recents list, and the listing prints. Scatter that per navigation command and one route always ends up forgetting one of the four.
</Callout>
