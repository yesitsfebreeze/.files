The language server does the heavy lifting and Neovim's own built-in keys drive most of it — this config adds a plugin only where the platform has no answer. Sessions are per-directory, so reopening a project restores what you had open.

## `<Tab> <S-Tab> <C-n> <C-p> <C-Space> <C-e>`

**Drive the completion menu**

*nvim insert*

`<Tab>` selects and accepts, and jumps to the next snippet placeholder once you are inside one; `<S-Tab>` goes back. `<C-n>`/`<C-p>` cycle, `<C-Space>` toggles the menu, `<C-e>` hides it. Documentation for the selected item appears on its own after a moment, and signature help shows while you are inside a call.

<Callout title="Why it is this way">
`<CR>` accepts the selected item and `<Esc>` cancels the menu, but both fall back to their ordinary meaning when no menu is open — that fallback is load-bearing: without it you could not insert a newline or leave insert mode.
</Callout>

Spec: `prds/03-editor/05-completion/prd.md`

## `<BS> and <CR> (autopairs)`

**Delete a bracket pair, and let Enter fall through to it**

*nvim insert*

`<BS>` next to an auto-inserted closing bracket or quote deletes both characters as one press, the same key as anywhere else. `<CR>` right after an opening bracket splits it onto three lines with the cursor indented in between — `{` then Enter gives `{`, a blank indented line, `}` — but only when no completion menu is showing; with one open, `<CR>` accepts the highlighted item instead, exactly as the entry above describes.

<Callout title="Why it is this way">
Both keys look like they belong entirely to completion, and only one does. blink.cmp maps `<CR>` to `{"accept", "fallback"}`: `fallback` means "run whatever `<CR>` did before blink.cmp claimed it", and because autopairs sets up first in load order, that prior mapping is autopairs' own bracket-expand handler — so the expand survives, but only through blink.cmp's fallback chain, and only while no menu is open. `<BS>` has no such chain: it is the one map autopairs sets that nothing else claims, so its default wins outright.
</Callout>

Spec: `prds/03-editor/12-small-plugins/prd.md`

## `gd and gI`

**Jump to a definition or an implementation**

*nvim normal*

`gd` on a symbol goes to where it is defined, `gI` to where it is implemented. `<C-o>` comes back.

<Callout title="Why it is this way">
These two are aliases for keys Neovim already provides, kept because the fingers know them. They attach per buffer on `LspAttach`, so they only exist where a language server is running — introspecting them needs an attached buffer, not a bare `nvim --headless`.
</Callout>

## `Neovim's own LSP keys`

**Use the LSP keys Neovim already ships**

*nvim normal*

`K` hovers. `grn` renames, `gra` acts, `grr` lists references, `gri` implementations, `gO` the symbols in the file. `]d` and `[d` walk diagnostics, which show inline with a `●`; to read one in full press `<C-w>d`, which is the key that opens the bordered float naming the server it came from.

<Callout title="Why it is this way">
Documented although they are not ours: Neovim provides them itself from 0.11 onward, this config deliberately does not re-map them, and they are how you use this editor. They are the one exception to the rule that plugin- and core-provided maps are allowlisted out of the drift check rather than documented.
</Callout>

See also: [`gd and gI`](/docs/guide/code#gd-and-gi) · [`<leader>rn and <leader>ca`](/docs/guide/code#leader-rn-and-leader-ca)

## `<leader>rn and <leader>ca`

**Rename a symbol or take a code action**

*nvim normal*

`<leader>rn` renames across the project — type the new name, enter. `<leader>ca` offers the actions the server has for the thing under the cursor. Both are buffer-local, so they appear once a server attaches.

## `<leader>cf`

**Format the buffer now**

*nvim normal*

Press `<leader>cf` and the buffer formats asynchronously. You rarely need it: saving formats already — stylua for lua, rustfmt for rust, black for python, prettier for markdown — and a filetype with no formatter of its own is formatted by its language server instead.

<Callout title="Why it is this way">
Prettier is the markdown formatter because it aligns table pipes, but prose must stay exactly as wrapped: these files are hand-wrapped at ~78 columns and reflowing them would churn every diff. On-save formatting gives up after 500 ms rather than blocking the write.
</Callout>

Spec: `prds/03-editor/07-formatting/prd.md`

## `<leader>t`

**Work with markdown tables**

*nvim normal*

In a markdown buffer, table mode is already on: type a row and the pipes realign as you type, with GitHub-style `|` corners. `<leader>t` is the prefix for the rest — `<leader>tt` tableizes the line or the selection, `<leader>tm` toggles the mode, `<leader>tr` realigns. Moving between cells is not under the prefix: `[|` and `]|` step left and right, `{|` and `}|` up and down.

<Callout title="Why it is this way">
Table mode is switched on by a FileType autocmd, not by the plugin itself: `vim-table-mode` ships inactive and needs `TableModeEnable` per buffer. Without the autocmd only the file you opened nvim with would align, and every markdown buffer you `:edit` afterwards would not.
</Callout>

See also: [`<leader>cf`](/docs/guide/code#leader-cf)  
Spec: `prds/03-editor/15-markdown-tables/prd.md`

## `<leader>ss <leader>sl <leader>sd`

**Restore the buffers you had open here**

*nvim normal*

The session for a directory is written automatically when you quit Neovim with at least one real file open. `<leader>ss` restores the one belonging to the directory you are in, `<leader>sl` restores the most recent session from anywhere, and `<leader>sd` turns the save off for this run when you do not want what you are about to do remembered. Nothing is restored unless you ask: starting `nvim` plainly gives you an empty editor, as it always did.

<Callout title="Why it is this way">
This is what tmux-resurrect brings back after a reboot: it re-launches nvim in the pane's directory with the restore command, and without a written session that pane would come back as an empty editor in the right place. The keys sit on `<leader>s` and not persistence.nvim's documented `<leader>q` because `<leader>q` is already Quit here, and making it a prefix would leave every quit waiting `timeoutlen` for a second key.
</Callout>

See also: [`<leader>w and <leader>q`](/docs/guide/editing#leader-w-and-leader-q)
