## `cc [...args]`

**Start Claude in this directory**

*shell*

`cc` launches Claude Code with permission prompts skipped, in the directory you are in. Arguments pass straight through.

<Callout title="Why it is this way">
With a single login profile it starts immediately — no picker. The multi-login machinery only wakes up once a second profile exists, so the common case pays nothing for it.
</Callout>

## `cll [model]`

**Start Claude Code on a chosen model**

*shell*

Run `cll` with no argument and a picker opens, grouped by provider; pick a row and Claude Code starts on that model. `cll <model>` skips the picker. Rows named `native:*` bypass the proxy and run on the Max plan; everything else goes through the local proxy with its fallback chain.

<Callout title="Why it is this way">
The picker lives in the script rather than in the shell, so every shell gets the same one. An earlier split — a nushell picker calling a script launcher — meant a stale shell called the script with no model at all and fell into a fallback path nothing had ever exercised.
</Callout>

## `llm quota`

**Read or record the balance per provider**

*shell*

`llm quota` prints the balances. `llm quota refresh` re-fetches the ones that have an API; `llm quota set <provider> <amount>` records the ones only a dashboard can tell you.

<Callout title="Why it is this way">
Two kinds of provider, one command: some publish a balance endpoint and some publish nothing at all, and the second kind is why `set` exists rather than an empty column.
</Callout>

## `llm regen`

**Rebuild the proxy's routing from live inventories**

*shell*

Run `llm regen` after a provider gains or loses models: it rewrites the proxy's routing config from what the providers actually serve now, and tells you to restart the proxy to pick it up.

<Callout title="Why it is this way">
The routing config is derived, never hand-edited — a hand-edited route outlives the model it names and fails at the moment you most want the model.
</Callout>

## Search with rg, find with fd, pick with tv

*shell*

Nothing to run — four rules that stop an agent guessing. Search with `rg` and find with `fd`, never `grep`/`find`. Pick with television (`tv`) — the single exception is `zi`/`cdi`, which open fzf, and it is the only place fzf belongs. Nushell commands return structured data, so filter with `| where`, not `| grep`. And `cd` here can create the directory it is given.

<Callout title="Why it is this way">
Every one of these is a failure this environment has actually seen: reaching for a tool that is not installed, or piping a table into a line-oriented filter and getting nothing.

## Understand how an agent comes up authenticated

*container*

Nothing to run: inside a capsule, `claude` and `opencode` both come up already authenticated, with no login prompt.

<Callout title="Why it is this way">
The Claude and OpenCode tokens are exported from the host's login keychain into a read-only mount, then symlinked into place (`setup-credentials.sh:208-213`, `:224-229`) rather than copied. A writable copy would let the container run its own OAuth refresh, and Claude's refresh rotates the refresh token — so a capsule refreshing on its own would invalidate the host's login. Borrowing the host credential and failing closed is the trade: if the access token expires while a long-lived capsule sits idle, the agent asks to log in, and re-mounting (or running the agent on the host) heals it.
</Callout>

See also: [`capsule [dir]`](/docs/guide/containers#enter-capsule) · [`credentials in a capsule`](/docs/guide/containers#credentials-in-a-capsule) · [`cc [...args]`](/docs/guide/agents#cc-args)
