# chezmoi keeps an entryState for a deployed file whose source was never in the repo

All thirteen television cable channels that this repo's chezmoi source has never carried nevertheless have an entryState in chezmoi's persistent state, each with a contentsSHA256 matching the deployed file byte for byte. Measured with chezmoi 2.72.1: git log over 217 commits shows none of the thirteen was ever a file under home/dot_config/television/cable, yet chezmoi state dump lists every one of them.

Consequence: the retirement of such a file is the QUIET case, not the loud one. A scoped 'chezmoi apply <target path>' with the path tombstoned in home/.chezmoiremove removed bg.toml silently at exit 0, with no controlling terminal, no prompt and no --force.

A separate canary planted at a path with NO entryState at all (zz-canary-probe.toml) was also removed silently at exit 0 under the same conditions. So neither shape reproduced the 'has changed since chezmoi last wrote it?' prompt and the 'could not open a new TTY' exit 1 that [[260902-7c3a]] records. That loud shape needs a THIRD condition — a target whose bytes differ from what chezmoi last wrote — not merely a missing or present state entry.
