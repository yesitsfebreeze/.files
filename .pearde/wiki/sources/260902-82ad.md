# chezmoiremove fires on every apply, so it uninstalls a replacement that owns the same path

.chezmoiremove fires on EVERY apply, not once, and deletes a symlink as readily as a regular file. Measured on chezmoi v2.72.1 with a throwaway source and destination: a foreign file written at the named target path AFTER the first apply was deleted on the second apply and again on the third, and a symlink pointing outside the destination went the same way.

So an entry naming a path that a DIFFERENT project installs into is a permanent uninstaller for that project, not a one-shot cleanup. It is the right tool only where nothing will ever reinstall the name.

Where a replacement owns the same name, write no entry: remove the deployed orphan by hand once, or let the replacement's install overwrite it, and let a fresh machine simply never have it.
