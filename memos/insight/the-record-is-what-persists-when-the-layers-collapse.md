# the-record-is-what-persists-when-the-layers-collapse

The dotfiles repo and the kern repo both arrived at the same shape from
different starts: a folder of Markdown files, frontmatter carries the
meaning, a `kind:` field names what a file is, the index is generated
whole, and the gate refuses the unindexed, the dead-linked, the
undeclared, the bundled. The kern tree measured this on itself with
`one-memory` (five registers, six spellings of the type field, no runner,
the graph that could fold all of it fed none of it) and retired four of
the five; the dotfiles tree measured it on `.pearde/{memos,wiki,graphify,health,grammar.md}`
(the board's registers and the knowledge vault and the derived graph
vault) and retired four of the five.

A different layer count arrives at the same shape, with the same gate and
the same kind vocabulary, because the shape is what survives the
collapse. The collapse is the test: a layer that is its own index, its own
schema, its own parser is a register, and a register ages apart from the
file it indexes. A folder of files with frontmatter and one generated
index does not.

The corollary: a new kind is a `kind: type` declaration in
`memos/system/`, and the gate refuses the undeclared. Adding a kind is one
file. Adding a new layer would need a new index, a new gate and a new
parser — the same machinery three times. The shape is biased against
layers because the layers were the cost.
